# مراجعات الكود المطلوبة من أعضاء الفريق

ينص التكليف على مراجعة واحدة موثقة على الأقل لكود زميل لكل طالب. الجدول الآتي خطة تحقق مقترحة متوافقة مع توزيع العمل؛ ليس دليلاً على تنفيذ مراجعات.

| المراجع | يراجع عمل | الملفات | ما ينبغي فحصه |
|---|---|---|---|
| مهند الشعار | بيان علي إيتي | `src/data.py`, `src/analysis.py` | صحة دمج الجداول ومقام النسب والرسوم |
| بيان علي إيتي | مازن اليافي | `src/model.py`, `src/validation.py` | عدم تسرب النتائج المستقبلية ومعايير الاختيار |
| مازن اليافي | محمد القصير | `docs/build_report.py`, `docs/report_finalize.py` | تطابق التقرير مع الأرقام والرسوم والاختبارات |
| محمد القصير | مهند الشعار | `run_pipeline.py`, `tests/`, `README.md` | إعادة التشغيل وصحة الاختبارات والتعليمات |

لكل مراجعة فعلية: يفتح الطالب الملف المعني، ويسجل تاريخ المراجعة ورقم Commit والملف والأسطر أو الدوال وما اختبره والنتيجة. يفضل توثيق ذلك في Pull Request Review أو تعليق محدد على GitHub مع رابط. يُحدّث `TEAM_CONTRIBUTIONS.csv` فقط بعد حصول هذه الأدلة. لا يجوز تسجيل مراجعة صورية.
