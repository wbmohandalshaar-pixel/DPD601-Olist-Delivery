# Ecommerce delivery analysis and approval time prediction

مشروع DPD601 F25 على جداول Olist السبعة المعتمدة. النسخة الثانية تعالج اختيار العينة عند الحدود الزمنية، وتقارن ثلاثة أنواع تعلم آلي مع مرجع بسيط، وتوثق القيود والنتائج الفعلية دون ادعاء درجة جامعية أو أداء تشغيلي مضمون.

## التشغيل على Windows

يفضل Python 3.12 بإصدار 64-bit. افتح Terminal داخل مجلد المشروع:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run_pipeline.py
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe docs\build_report.py
```

على Linux أو macOS:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run_pipeline.py
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python docs/build_report.py
```

تثبيت المكتبات يحتاج اتصالاً بالإنترنت، أما التشغيل فيستخدم الملفات المحلية. زمن التشغيل يختلف حسب الجهاز. الإصدارات الفعلية في outputs/tables/environment.json. شُغلت النسخة في البيئة المتاحة؛ لم ينفذ اختبار Windows مستقل، ويجب تشغيلها على جهاز الفريق قبل التسليم.

## البنية

- `config.json`: البذرة والحدود الزمنية والفاصل ومعيار الاختيار وحالة الاختبار التاريخي.
- `src/data.py`: قراءة الخام والتدقيق والتجميع المستقل والربط والخصائص وتعريف الهدف.
- `src/validation.py`: اختيار الفترات بتاريخ الاعتماد وفحص وقت معرفة النتيجة.
- `src/features.py`: التحويل اللوغاريتمي والتمثيل الدوري الثابت دون تعلم من الاختبار.
- `src/model.py`: المقارنة الزمنية والمعايرة وضبط العتبة والتقييم وتصدير النموذج.
- `src/analysis.py`: الأسئلة والجداول والرسوم الوصفية والتقييمية.
- `src/diagnostics.py`: رسم المقارنة عبر الفترات والمعايرة ومصفوفات الالتباس.
- `run_pipeline.py`: نقطة تشغيل واحدة لإعادة إنتاج البيانات والنتائج والرسوم والنموذج.
- `predict.py`: درجات وتنبؤات من CSV خصائص مجهز مسبقاً؛ لا يقرأ الجداول الخام مباشرة.
- `tests/test_project.py`: اختبارات unittest قابلة للتشغيل، لا تحتاج pytest.
- `data/raw/`: الجداول السبعة الأصلية دون تعديل؛ `data/processed/`: نواتج مولدة برمجياً.
- `outputs/tables/`: التدقيق والأجزاء والتجارب والتنبؤات والمعايرة والأخطاء والميزانيات التشخيصية.
- `outputs/figures/`: 15 رسماً تحليلياً وتقييمياً، إضافة إلى مخطط العلاقات.
- `outputs/models/selected_model.joblib`: المعالجة والنموذج والمعاير والعتبة والإعدادات.
- `outputs/legacy_v1/` و`outputs/v2_round1/`: أدلة تاريخ التجربة السابقة، ليست نتائج النسخة الحالية.
- `docs/Report_AR.docx`: التقرير العربي المباشر، يعاد بناؤه من النتائج دون أرقام أداء ثابتة.
- `docs/feature_dictionary.csv` و`feature_dictionary_ar.csv`: قاموس الخصائص وصيغها العربية.
- `docs/DATA_DECISIONS.md`: قرارات المعالجة وافتراضات الإتاحة والمنهجية والقيود.
- `docs/DEFENSE_GUIDE_AR.md`: دليل المناقشة المحدث؛ `docs/REVIEW_AR.md`: مراجعة النسخة الحالية.
- `docs/RUBRIC_CHECKLIST_AR.md`: مطابقة المتطلبات؛ `TEAM_CONTRIBUTIONS.csv` و`GIT_WORKFLOW_AR.md`: تنظيم العمل الحقيقي للفريق.
- `docs/history/EXPERIMENT_HISTORY.md`: سجل تطوير يوضح أن الفترة النهائية سبق الاطلاع عليها.

## المنهجية

وحدة التحليل طلب واحد. تجمع العناصر والمدفوعات كل على حدة قبل الربط، وتختبر المجاميع والتفرد. is_late يقارن يوم الوصول باليوم المتوقع؛ مجهول النتيجة والملغى لا يصبحان فئة سلبية.

عضوية الفترات تعتمد على تاريخ الاعتماد وحده. فاصل انتظار ثابت 90 يوماً قبل طيات التقييم يبعد التدريب زمنياً دون حذف الطلبات حسب سرعة الوصول. للطلب الملتزم تعرف النتيجة عند الوصول، وللمتأخر عند بداية اليوم التالي للموعد المتوقع إذا لم يصل قبله. إذا وجدت نتيجة غير متاحة عند الساعة المحددة، يتوقف التشغيل ولا يحذف الصف وحده. يعتمد ذلك على صحة التواريخ المسجلة؛ اللقطة ليست سجلاً كاملاً للحالات، والمجتمع مشروط بالتسليم النهائي وفق التكليف.

تقارن 13 حالة، تشمل المرجع و12 إعداداً، على طيات تحقق حزيران وآب وتشرين الأول 2017: **39 ملاءمة**. المقارنة تختار أعلى متوسط AP عبر الطيات. توجد مقارنة للانحدار اللوجستي الخام واللوغاريتمي الدوري، والغابة العشوائية، وHistogram Gradient Boosting. التعويض والتحجيم والترميز تتعلم من التدريب فقط.

بعد الاختيار، يدرب نموذج أساسي على فترة الاعتماد السابقة لتشرين الأول 2017 وفق الحد المحسوب في config. التحقق في كانون الثاني 2018: الأيام 1-15 لمعايرة sigmoid، ومن 16 إلى نهاية الشهر لعتبة F1. الجزآن منفصلان ويستخدمان للتطوير بعد اكتمال نتائجهما وقبل أيار. ليست هذه محاكاة توقع حي لكل يوم من كانون الثاني. الفترة الأحدث تبدأ في أيار 2018.

**حالة الاختبار مهمة:** فترة أيار إلى آب 2018 سبق الاطلاع عليها في النسخة الأولى وفي مرور التطوير الموثق. لا تصبح عينة غير مشاهدة بعد المراجعة. اختيار الإعدادات الحالي يستخدم CV والتحقق فقط، لكن النتائج النهائية تقييم تاريخي شفاف وليست تأكيداً مستقلاً جديداً. يلزم بيانات جديدة لتأكيد التعميم.

المعايرة لا يضمن تحسنها في كل فترة. تظهر نتائج Brier الخام والمعايرة حتى لو كان الخام أفضل. ميزانيات المتابعة وأهمية الخصائص والأخطاء تشخيصية بعد تثبيت الاختيار ولا تضبط العتبة على الاختبار.

## استخدام النموذج

```bash
python predict.py --input data/processed/model_orders.csv --output outputs/predictions_example.csv
```

يختار البرنامج المدخلات المسموحة فقط ويطبق المعاير المحفوظ والعتبة. يسمى المخرج late_score؛ لا نفترض أن الدرجة احتمال تشغيلي مثبت دائماً. لا تفتح ملفات joblib من مصادر غير موثوقة.

`python run_pipeline.py --skip-training` يعيد التدقيق والرسوم الوصفية فقط، وليس بديلاً عن التشغيل الكامل لتحديث نتائج النماذج. أي نتائج نماذج موجودة بعد هذا الخيار قد تخص تشغيلاً سابقاً؛ استخدم التشغيل الكامل قبل بناء التقرير النهائي.
